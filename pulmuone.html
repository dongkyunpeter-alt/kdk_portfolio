01 / System

디자인 시스템 재구축

문제초기 구조를 충분히 이해하지 못해 페이지 제작을 다시 시작해야 했습니다.

해결토큰 참조 구조를 다시 학습하고 하네스와 자동 검사까지 포함해 재구축했습니다.

결과토큰·구현·검증 기준을 하나의 작업 체계로 연결

02 / Consistency

공통 영역 일괄 적용

문제페이지마다 헤더·head·푸터가 달라 수정 누락과 동작 차이가 발생했습니다.

해결공통 원본과 동기화 도구를 구성해 같은 구조와 설정을 사용하도록 통일했습니다.

결과한 번의 수정으로 6개 페이지 공통 영역을 동일하게 반영

03 / Verification

생성 결과 품질 검증

문제생성 결과가 화면 목적과 구현 기준을 안정적으로 충족하는지 판단할 공통 기준이 필요했습니다.

해결반응형·접근성·성능 기준으로 직접 검토하고, 통과하지 못한 결과는 코드와 에셋을 수정했습니다.

결과도구와 관계없이 최종 품질을 직접 판단하고 책임지는 검증 흐름 확립
