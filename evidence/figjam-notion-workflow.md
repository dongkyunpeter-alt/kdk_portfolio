# FigJam → Notion 자동 회의록 워크플로

팀 FigJam 보드의 변경 내용을 확인하고, 작성자와 업무 유형별로 정리해 Notion 회의록에 반영하는 작업 절차다.

## 연결 자료

- [FigJam 회의보드](https://www.figma.com/board/tTNn7XY4aHoeSO7p1fTaWX/%ED%82%A4%EC%9C%85-%ED%9A%8C%EC%9D%98%EB%B3%B4%EB%93%9C?node-id=0-1)
- [Notion 회의록](https://app.notion.com/p/123566c2471d82c89423017b9d966342?v=58a566c2471d837cafed889ad635aae2)

## 처리 절차

1. FigJam 회의보드의 내용을 이전 기록과 비교한다.
2. 새로 추가되거나 수정된 내용만 추출한다.
3. 카드와 도형의 색상을 기준으로 작성자를 구분한다.
4. 내용을 기획, 디자인, 화면 설계, 개발, 배포·검사 중 알맞은 업무 유형으로 분류한다.
5. 공유된 원본 링크를 포함해 Notion 회의록 카드로 추가하거나 수정한다.
6. 반영 결과를 검사하고 오류가 있으면 한 차례 수정한다.

## 작성자 분류 기준

| FigJam 색상 | 작성자 |
|---|---|
| 연보라 `#D3BDFF` | 이수지 |
| 분홍 `#FFA8DB` | 김지원 |
| 민트 `#B3F4EF` | 변혜인 |
| 살구 `#FFAFA3` | 강동균 |
| 노랑 `#FFE299` | 송원일 |

색상 정보가 제공되는 스티커는 해당 값을 사용하고, 도형처럼 색상 정보가 포함되지 않는 요소는 화면을 확인해 분류한다. 위 색상에 해당하지 않는 내용은 공통 작업으로 처리한다.

## 기록 규칙

- 제목은 날짜와 12자 이내의 요약으로 작성한다.
- 원본에 없는 내용은 임의로 보완하지 않는다.
- 보드에 공유된 링크는 회의록에도 함께 기록한다.
- 팀원별 내용을 제목과 목록으로 구분한다.
- Notion 카드 상태는 `하는 중`을 기본값으로 사용한다.
- 정기 확인 시각은 매일 오후 5시 40분이다.

## 확인된 결과 예시

Notion의 `7월27일 ESG성과연혁정리` 기록은 FigJam 보드의 `521:230` 영역을 출처로 연결하고, 내용을 작성자와 기획 업무로 분류해 정리한 결과다.
